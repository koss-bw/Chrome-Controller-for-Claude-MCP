# Chrome Controller for Claude MCP

An MCP server and Chrome extension that let Claude Code drive your already-open browser: navigate, read and interact with pages, manage tabs, bookmarks, history and downloads, reverse-engineer a site's API into an OpenAPI spec, and record your own browsing sessions as imitation-learning traces.

It builds on [open-claude-in-chrome](https://github.com/noemica-io/open-claude-in-chrome) by Sebastian Sosa (Noemica) and has since grown a browser-state toolset, an API reverse-engineering pipeline, a recording side panel, and a local Claude Code sidecar. The repo is self-contained: everything the server reads or writes lives under it.

## What's in here

```
.
├── host/ # Node side. Launched by Claude Code and by Chrome.
│   ├── mcp-server.js # stdio MCP server Claude Code talks to
│   ├── native-host.js # native-messaging bridge Chrome launches; writes recordings and API bundles to disk
│   ├── tool-definitions.js # the 33 tool schemas and descriptions
│   ├── tool-runtime.js # TCP primary/client logic, forwards calls to the extension
│   ├── ocic-call.mjs # CLI helper: call one tool from a shell
│   ├── codemode/ # optional execute_code variants (server-codemode.js, server-hybrid.js, Cloudflare worker)
│   └── native-host-wrapper.sh # generated by install.sh, gitignored
├── extension/ # Unpacked Chrome MV3 extension
│   ├── background.js # CDP automation, tool dispatch
│   ├── apimap.js # api_* tools (capture, crawl, source scan, spec)
│   ├── recorder/ # imitation-learning recorder and Options page
│   └── sidepanel/ # Claude chat panel (Web and Code backends)
├── server/ # FastAPI sidecar the side panel's Code backend uses to run `claude -p`
├── custom_apis/ # OUTPUT, gitignored: one bundle per reverse-engineered site
├── recordings/ # OUTPUT, gitignored: imitation-learning bundles
├── install.sh # registers the native host with Chrome, Brave and Edge
├── refresh-mcp.sh # kills stale host processes so /mcp reconnects cleanly
├── CLAUDE.md # working notes for Claude sessions run from this directory
└── SECURITY.md # what this tool can reach and how to report a problem
```

`custom_apis/` and `recordings/` contain live cookies, bearer tokens and captured request bodies. They are gitignored along with `node_modules/`, the generated wrapper, `server/.venv/` and anything named `*token*` or `*cookie*`. Nothing in them should ever be committed.

## How it runs

```
Claude Code <--stdio--> host/mcp-server.js <--TCP 127.0.0.1:18765--> host/native-host.js <--native messaging--> extension <--CDP--> Chrome
```

- Claude Code starts `mcp-server.js` per session. The first one binds port 18765 and becomes primary; later sessions connect to it as clients, so several Claude Code sessions share one browser.
- Chrome starts `native-host.js` (via the generated wrapper) when the extension calls `connectNative()`, and it dials the primary over TCP.
- The extension does the actual work through the Chrome DevTools Protocol and the `chrome.*` APIs.

## Setup

Prerequisites: Node 18+, Python 3.12 (sidecar only), any Chromium browser, Claude Code.

```bash
git clone https://github.com/koss-bw/Chrome-Controller-for-Claude-MCP.git
cd Chrome-Controller-for-Claude-MCP
(cd host && npm ci)
(cd host/codemode/worker && npm ci) # only if you use the codemode/hybrid servers
```

1. `chrome://extensions` → Developer mode → **Load unpacked** → select `extension/`. Copy the ID shown on the card.
2. `./install.sh <extension-id>` writes `host/native-host-wrapper.sh` and the native-messaging manifest for Chrome, Brave and Edge. Pass one ID per browser if you load the extension in more than one.
3. Register the server with Claude Code, from the repo root:
   ```bash
   claude mcp add browse -- node "$PWD/host/mcp-server.js"
   ```
4. In a Claude Code session: `/mcp` → reconnect `browse`, then ask for `tabs_context_mcp`. A list of your open tabs means the whole chain is up.

Chrome derives an unpacked extension's ID from its directory path. If this folder moves, remove and re-load the extension, then re-run `install.sh` with the new ID.

### Optional: side panel sidecar

The extension's toolbar icon opens a chat panel. Its **Web** backend uses your claude.ai login and needs nothing. Its **Code** backend runs a headless Claude Code session on this machine with the browser tools attached:

```bash
./server/run.sh # creates server/.venv on first run, serves 127.0.0.1:8765 with --reload
```

Settings are optional and live in `~/.config/chrome-controller-mcp/panel.json` (`cwd` defaults to this directory; `allowed_tools` defaults to `mcp__browse__*`, `Read`, `Grep`, `Glob`). The panel authenticates with the token in `~/.config/chrome-controller-mcp/panel-token`, created on first run. See [Security](#security) for the two defaults you may want to tighten.

## Tools (33)

**Page automation** (the original 18, matching Anthropic's Claude in Chrome)

| Tool | Does |
|---|---|
| `tabs_context_mcp` | List open tabs and which one the user is looking at. Call first. |
| `tabs_create_mcp` | Open a tab |
| `navigate` | URL, back, forward |
| `computer` | Screenshot, click, type, scroll, keys |
| `read_page` | Accessibility tree with element refs |
| `get_page_text` | Main-content text |
| `find` | Locate elements by text or attributes |
| `form_input` | Set form values by ref |
| `javascript_tool` | Run JS in the page |
| `read_console_messages`, `read_network_requests` | Console and network log |
| `resize_window` | Change the viewport |
| `upload_image` | Put a screenshot into a file input |
| `update_plan` | Present a plan |
| `gif_creator`, `shortcuts_list`, `shortcuts_execute`, `switch_browser` | Stubs kept for parity |

**Browser state** (added here; things no page script can see)

| Tool | Does |
|---|---|
| `tabs_close_mcp` | Actually close tabs (by default only ones Claude opened) |
| `browser_chrome_mcp` | Windows and their bounds, bookmarks bar, top sites, recently closed, reading list |
| `bookmarks_mcp` | List, search, create, move, delete bookmarks |
| `history_mcp` | Search history; delete a URL behind `force` |
| `downloads_mcp` | List, pause, resume, show, cancel downloads |
| `extensions_mcp` | List installed extensions; enable/disable/uninstall behind `force` |
| `window_control_mcp` | Minimize, maximize, fullscreen, focus, move a window |

**API discovery** (added here; output goes to `custom_apis/<slug>/`)

| Tool | Does |
|---|---|
| `api_capture` | Record a tab's traffic with real headers and bodies; `auth` snapshots cookies, storage and auth headers into `auth.json` |
| `api_crawl` | Navigate the app's routes, optionally clicking controls (`interact`), recording what each fires |
| `api_fetch_source` | Pull the app's JS bundles and sourcemaps into `static/` |
| `api_scan_source` | Mine those bundles for endpoints → `static/findings.json` |
| `api_wellknown` | Look for a published OpenAPI/Swagger doc or GraphQL introspection |
| `api_hosts` | Host inventory from traffic, CSP, bundles, robots/sitemap, certificate transparency → `hosts.json` |
| `api_probe` | Replay one endpoint to confirm params and whether auth is required (`GET`/`HEAD`/`OPTIONS` only without `force`) |
| `api_spec` | Merge everything into `endpoints.json` and an OpenAPI 3 `openapi.json` |

Anything that clicks in a logged-in session, replays a write, or deletes browser data is refused without `force: true`. `CLAUDE.md` tells sessions to read an existing bundle before crawling a site again, and records what a crawl cannot see.

## Output directories

| Directory | Written by | Contents |
|---|---|---|
| `custom_apis/<slug>/` | native host, for `api_*` | `openapi.json`, `endpoints.json`, `hosts.json`, `routes.json`, `requests/`, `static/`, `probes/`, `screenshots/`, `auth.json` (plaintext credentials), optional `client/` and `NOTES.md` |
| `recordings/<id>/` | native host, for the recorder | `trace.json`, `SCHEMA_v0.md`, `images/` |

Both defaults are resolved relative to the repo in `host/native-host.js`. Override with `recordings_dir` / `custom_apis_dir` in `~/.config/chrome-controller-mcp/config.json`, which also takes `port`.

## Codemode and hybrid servers

`host/codemode/server-codemode.js` exposes `execute_code`, `screenshot` and `zoom`: Claude writes JavaScript against a typed `chrome.*` API and it runs in a sandboxed Cloudflare Worker (`wrangler dev`), collapsing a multi-step flow into one round trip. `server-hybrid.js` exposes that plus all the direct tools and is what the recorder's channel needs. Both spawn `mcp-server.js` as their upstream and are registered separately if you want them:

```bash
claude mcp add browse-hybrid -- node "$PWD/host/codemode/server-hybrid.js"
```

First call pays a few seconds while `wrangler dev` boots.

## Imitation-learning recorder

Press **Record** in the side panel, do a task while narrating, press **Stop**. The extension writes a bundle to `recordings/<YYYY-MM-DD>_<HHMMSS>_<site>/` with actions resolved to durable element anchors, cursor trajectory, low-res frames and transcribed narration, and copies a reference to your clipboard to paste into Claude Code. Transcription needs an OpenAI key and microphone permission, both set on the extension's Options page. If a Claude Code session was launched with `--dangerously-load-development-channels server:browse-hybrid`, it is notified when a recording completes.

## Security

Read this before installing. The extension is a remote control for your real browser profile.

- **Permissions.** The manifest asks for `debugger`, `<all_urls>`, `tabs`, `history`, `bookmarks`, `downloads`, `management`, `sessions`, `topSites` and `readingList`. Every tool runs inside your logged-in sessions with your cookies. There is no sandbox and no domain blocklist.
- **Plaintext credentials on disk.** `api_capture` with `auth: true` writes your session cookies and bearer tokens for that site to `custom_apis/<slug>/auth.json` so a generated client works immediately. Treat that directory like a password file. It is gitignored; do not un-ignore it.
- **Local ports.** The MCP host listens on `127.0.0.1:18765` and the sidecar on `127.0.0.1:8765`. Neither is exposed off-host, but any local process can reach them.
- **Sidecar defaults worth tightening.** In `server/config.py`, `permission_mode` defaults to `acceptEdits` and `bootstrap` defaults to `True`, which lets any installed extension fetch the panel token. Set `bootstrap: false` and `permission_mode: "default"` in `panel.json` if you share the machine or run untrusted extensions.
- **Naming.** Internal identifiers (`__ocic` messages, `X-OCIC-*` headers, `OCIC_*` env vars, `ocic-call.mjs`) keep the prefix inherited from the upstream project. They are protocol tokens, not references to anything outside this repo.

To report a vulnerability, see `SECURITY.md`.

## After editing code

| Changed | Do |
|---|---|
| `extension/**` | Reload the extension in `chrome://extensions` |
| `host/mcp-server.js`, `tool-*.js` | `./refresh-mcp.sh` (or `pkill -f "host/mcp-server"`), then `/mcp` in Claude Code |
| `host/native-host.js` | Restart the browser (all windows) |
| `host/codemode/**` | `pkill -f "server-codemode\|server-hybrid"; pkill -f wrangler`, then `/mcp` |
| `install.sh` | `./install.sh <extension-id>`, restart browser |
| `server/**` | Nothing; `run.sh` reloads on change |

## Troubleshooting

- **"Browser extension is not connected"**: the MCP server is up but no native host has dialed in. Open any page to wake the service worker; check `chrome://extensions` → service worker console; confirm `host/native-host-wrapper.sh` exists and the manifest at `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.chrome_controller.claude_mcp.json` (Linux: `~/.config/google-chrome/NativeMessagingHosts/`) has the current extension ID and path.
- **Tools fail right after reconnect**: a stale primary from an earlier session is holding 18765. `./refresh-mcp.sh`, then `/mcp`.
- **Extension ID changed**: the folder moved. Re-run `./install.sh <new-id>`.
- **Port conflict**: `{ "port": 19000 }` in `~/.config/chrome-controller-mcp/config.json`, then restart browser and Claude Code.
